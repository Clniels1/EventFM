Requirements for the web application

Technological:

You must use the following languages, frameworks and libraries:

    HTML, CSS and Bootstrap
    Python
    Flask (plus Flask-WTF, Flask-SQLAlchemy, Bootstrap-Flask, Flask-Login and an authentication library e.g., werkzeug or bcrypt)
    WTForms
    SQLAlchemy
    For AI-enhanced functionality, only sentence-transformers, huggingface_hub, and/or OpenAI libraries/APIs may be used.

Functional:

    A landing page that clearly conveys the purpose of the website and showcases upcoming events. Users must be able to browse events by category through an intuitive interface. In addition, the application must support traditional keyword-based search and an AI-enhanced event discovery capability that improves a user's ability to locate relevant events beyond simple keyword matching. Examples include semantic search, event recommendations, related-event suggestions, or another approved AI approach (confirmed by your tutor).
    The events listed on the landing page should show a useful overview of the events with information in accordance with the context of the design (including the event’s status at a minimum).
    Anybody should be able to choose an event and view the details of it. The event details page should have an image of the event, a description of the event, the date and any other specific information that is helpful to the user and is in accordance with the context of the design and requirements.
    To buy tickets, the user should be logged in. The user should provide details such as the quantity of the tickets to be booked. An order is generated by the application, and the order detail (order ID) is provided to the user for reference. Consistent with the booking history view developed in assignment 1, that view should now reflect the user's actual, previously booked events.
    A logged-in user can post a comment on an event. The name of the commenter, the comment, and the date the comment was posted can be seen by anybody.
    A logged-in user can create an event by entering relevant details. In addition, an event must have one of the following states: Open, Inactive (event date in the past), Sold Out, or Cancelled. The owner of the event should be able to update the details of the event (excluding the event status). They can also cancel their own events. The creator of an event should be able to build an appropriate Acknowledgement of Country Statement directly into the event details (see more information about this feature below).
    A logged-in user can log out of the application.
    Anybody can register for the site by providing details of their first name, surname, email, password, contact number, and street address.
    Error Handling - Ensure that the two errors 404 and 500 are handled appropriately.
    All your pages should include a navigation menu and utilise data that is dynamically drawn from and stored in the database.

Development Guidelines

    Develop code that is well written with reasonable comments.
    You should use the assessment starter code zip file that is provided to assist you with organising your code. Please change the folder name from ‘projectfile’ to ‘a2_groupX’ (where X is your group number from Canvas) and the module name from ‘website’ to the name of your application.
    Only use the technologies listed above. JavaScript is not used in this unit and should not be used as it may distract you from completing work that will get you marks. The code you submit will be tested and run, so there should be no unexpected dependencies.
    The application must incorporate at least one AI-enhanced event discovery capability. Examples include:
            Semantic search that finds events based on meaning rather than exact keyword matches.
            Related event recommendations.
            Personalised event recommendations based on previous bookings or interests.
            Intelligent event discovery features that improve the user's ability to locate relevant events.

Database Design

A database solution will be required to achieve desired functionality in your solution. Your database design will consist of at least four tables:

    An event table containing the event details – you can add more tables to store more information or you can choose to keep it simple if you see fit.
    A booking table storing information about the price, quantity and date with relationship to a user and an event.
    A user table storing information about users, including their login credentials.
    A comments table.
    Any other tables that you decide to include to normalise data (however, we recommend keeping things as simple as possible).

Guidance on creating a Meaningful Acknowledgement to Country feature
Acknowledgement of Country has become very typical and widely expected at Australian events. Therefore, the creator of an event should be able to build an appropriate Acknowledgement of Country Statement directly into the event details. The creator of an event should be able to select between:

    No Acknowledgement of Country
    Acknowledgement of Country: generic
    Acknowledgement of Country: enhanced

Your site should Explain what an Acknowledgement to Country is and why it is an important practice for reconciliation. It should also distinguish between an Acknowledgement to Country and a Welcome to Country.

If Acknowledgement of Country: enhanced is selected
If the event creator selects the enhanced option, students must design additional features and guidance, of their own choosing, that support the creation of a Meaningful Acknowledgement to Country. Students are encouraged to be creative and thoughtful in how this functionality is implemented. An Acknowledgement to Country is an important practice in Australia that recognises the Traditional Custodians of the land and their enduring connection to Country, and plays a role in reconciliation. This enhanced feature should enable users to create a tailored Acknowledgement that demonstrates respect, cultural awareness, and understanding, informed by appropriate research and ethical consideration.

Your site should:

    Identify the Traditional Custodians of Australian Capital Cities.
    Assist the user with identifying the Traditional Custodians of a specific place using reliable sources by providing a clear, student‑appropriate set of authoritative resources that can be used to identify Traditional Custodians / Traditional Owners of land in Australia. You will need to research this.
    Provide information on common mistakes and contested issues related to Acknowledgement to Country. The user needs to be careful that they are not tokenistic, inaccurate, or culturally inappropriate.
    Assist the user with creating a culturally respectful and meaningful Acknowledgement to Country supported by research.

You are to explore what makes an Acknowledgement to Country meaningful, examine common challenges and ethical considerations, and apply that learning to construct the features and guidance on your site.
